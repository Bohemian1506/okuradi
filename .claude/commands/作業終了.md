# /作業終了

`/始め` の対。**区切り漏れを止めるためにある**（#183・2026-09-24・ユーザーの判断）。

## 1. 区切ったかを見る

**main の申し送りの見出しの時刻より後に、作業の PR が main に入っていなければ、区切り済み**と見る（#202・案A に時刻を足した）。
`/区切り` は見出しを `## YYYY-MM-DD HH:MM（day-N の区切り）` の形で書き直す。作業の PR で申し送りを直しても、見出しは変えない。

```
git fetch -q origin main
git show origin/main:docs/handoff.md | grep -m1 '^## '
git log --first-parent -m --since='<見出しの日付と時刻>' --format='%cd %s' --date=format:'%F %R' \
  origin/main -- . ':!docs/handoff.md' ':!docs/dev-log/'
```

2つめが何も出さなければ区切り済み。**出たら、それが区切ったあとに入った作業の PR。**

> **申し送りが最後に更新された日では見ない。** それで見て外れた（#202）。
> 作業の PR の中で申し送りの古い記述を直すと、区切っていないのに「区切り済み」になる。
> **日付だけでも見ない。** 午前に区切って午後も作業した日に、午後の分が漏れる（2026-09-26・ユーザーの指摘）。
> 時刻で比べるので、日付をまたいで区切った夜も外れない。
> `--first-parent -m` は、PR のマージの時刻で見るため（付けないと、手元でコミットした時刻で見る）。
> 議事録と申し送りだけの PR は数えない（区切りの PR 自身と、マージのあとの議事録の PR）。
> **見出しに時刻が無い（古い形の）ときは、日付が今日かだけを見る。**

- **作業の PR が出たら「先に区切りますか」と聞く。** はい なら `/区切り` をやり、マージまで終えてから 2 へ
- いいえ なら、そのまま 2 へ（区切らない日もある）
- **開いている PR・`main` 以外のブランチ・未コミットの変更**があれば、ここで言う（`git status --short` / `git branch` / `gh pr list --state open`）。
  **捨てない。** 残したまま終えるかはユーザーが決める

## 2. 印を置く

```
mkdir -p .claude/state && touch .claude/state/作業終了
```

**次に続きから（`start.sh -c`）開いたときにも、`/始め` が促される。**
起動の hook（`session-start-begin.py`）が印を見て、出したら消す。

## 3. 作業のペインを閉じる

```
.claude/scripts/作業ペイン.sh close
```

いまのタブの、名前の付いた3つ（変更・GUIログ・今日の一手）だけを閉じる。**ほかのペインには触らない。**
**GUIログのペインで何か動いていたら、どれも閉じずに止まる**（終了コード 3）。
GUI のサーバーごと閉じると、裏で動いている工程（動画化など）が取り残され、作りかけのファイルも消されないため。
そのときは**ユーザーに、GUI で工程が終わっているかを聞く。** 終わっていれば、サーバーを止めてもらって（Ctrl+C）からもう一度打つ。

## 4. 終える

**Claude は `/exit` を自分では打てない。** 最後に「`/exit` で終わります」と1行出す。最後の1打はユーザー。
