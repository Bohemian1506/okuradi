# /review-team

対象: $ARGUMENTS

## 1. 対象を決める
- 数字: PR 番号（`gh pr view <N>`、`gh pr diff <N>`）。無ければ今のブランチの差分（`git diff main...HEAD`）
- `code` / `scope` / `design` / `user`: 呼ぶ担当の指定（複数可）
- それ以外の文字列: 重点の観点として各担当に伝える

関係する Issue 番号を、ブランチ名・PR 本文・コミットから拾う。

## 2. 呼ぶ担当を決める
担当の指定があれば、その担当だけを呼ぶ。無ければ、変更の中身から次の表で選ぶ。

| 担当 | 呼ぶ場面 |
|---|---|
| `code-reviewer` | コード・スクリプト・設定の変更があるとき |
| `scope-reviewer` | 機能の範囲や設計の判断を含むとき、大きな PR のとき |
| `design-reviewer` | デザイン・画面・画面の文言の変更があるとき |
| `user-reviewer` | 画面・操作の流れ・機能の範囲の変更があるとき |

起動する前に、呼ぶ担当と選んだ理由を1行ずつ書く。どれにも当たらない小さな変更なら、呼ばずにそう伝える。

## 3. 1つのメッセージで並べて起動する
各担当には、対象（差分の取り方 or PR 番号）、関係する Issue、重点の観点を渡す。担当どうしの結論は互いに見せない。

## 4. まとめる
最初にまとめを出し、そのあとに担当ごとの指摘を並べる。
- 🚨 の一覧（担当名つき）
- 複数の担当が同じことを言っている指摘
- 担当どうしで意見が分かれた点（どちらを採るかはユーザーが決める）
- このあとの対応案（直す / 見送る / Issue にする）

直すかどうかはユーザーに確認してから進める。
