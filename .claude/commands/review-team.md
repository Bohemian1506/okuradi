# /review-team

対象: $ARGUMENTS

## 1. 対象を決める
- 空、または文字列: 今のブランチの差分（`git diff main...HEAD`）。文字列は重点の観点として各担当に伝える
- 数字: PR 番号（`gh pr view <N>`、`gh pr diff <N>`）

関係する Issue 番号を、ブランチ名・PR 本文・コミットから拾う。

## 2. 担当は4人全員を呼ぶ
`code-reviewer` / `scope-reviewer` / `design-reviewer` / `user-reviewer` の4人を、規模や種類に関係なく呼ぶ。
差分に画面の変更が無いときも、design と user には「画面に出る文言・操作の流れ・機能の範囲への影響」を見てもらう。
担当を省くのは、ユーザーが省くと言ったときだけ（Claude から省くことを提案しない）。

## 3. 1つのメッセージで並べて起動する
各担当には、対象（差分の取り方 or PR 番号）、関係する Issue、重点の観点を渡す。担当どうしの結論は互いに見せない。

## 4. まとめる
担当ごとに指摘を並べたあと、最後にまとめを出す。
- 🚨 の一覧（担当名つき）
- 複数の担当が同じことを言っている指摘
- 担当どうしで意見が分かれた点（どちらを採るかはユーザーが決める）
- このあとの対応案（直す / 見送る / Issue にする）

直すかどうかはユーザーに確認してから進める。
