# /始め

やりたいこと: $ARGUMENTS

`/区切り` の対になるコマンド。**区切りで書いた申し送りを、次の朝に読み直す側。**

**手順より、間違えやすい所を思い出すために使う。**

## 前提: Issue の一覧は、もう出ている

`.claude/hooks/session-start-status.py` が、セッションの頭で
**開いている Issue・最近動いた Issue・開いている PR・手元の未コミットの変更**を出している。
**数え直さない。そこに出ている数字を使う。**

出ていないとき（別の場所から起動した / `gh` が固まった / ネットが切れている）だけ、自分で打つ:

```
gh issue list --limit 50 --json number,title,labels
gh pr list --state open
git branch --show-current && git status --short
```

## 1. 申し送りを読む

`docs/handoff.md`。**最新の1回分しか無い。** それより前の経緯は `docs/dev-log/`。

## 2. 突き合わせる（**ここがこのコマンドの本体**）

申し送りは Claude が書いたもの。**書いた時点では正しくても、いまは古い。**
hook が出した実物と並べて、次を見る:

- **Issue の件数と番号**（申し送りの表と、hook の件数）
- **開いている PR**（申し送りが「無し」と書いていても、増えていることがある）
- **ブランチ**（`main` 以外に残っていないか）
- **手元の未コミットの変更**（**ユーザーの作業かもしれない。捨てる前に中身を見る**）

**食い違ったら、実物が正しい。** 申し送りの方を直す（`/区切り` のときに上書きする）。

**hook が拾えないものが1つある: Issue のコメント。**
番組側（r-hoso）の返事は、メッセージではなく**コメント**として来る。
最近動いた Issue に心当たりがあれば、中を見る:

```
gh issue view <番号> --json comments
```

day-4 に、返事を3回「まだ来ていない」と書いた。見に行かなかっただけだった。

## 3. 「まだ確かめていないこと」を見る

申し送りの末尾。**ここに書いてあるものは、今日の作業で通りがかりに確かめられることがある。**
確かめられたら、その場で言う（`/区切り` のときに消す）。

## 4. 次の一手を、1つだけ出す

申し送りの「次にやること」と、今日やりたいこと（`$ARGUMENTS`）を突き合わせる。

- **Claude が動けるか、ユーザーが動く番かを先に言う。**
  申し送りに「Claude がいますぐできる Issue は無い」と書いてあることがある。
  そのときは、**無理に着手先を探さない**。何待ちかを言う
- **勝手に決めない。** 案が複数あるなら、それぞれで何が変わるかを説明し、おすすめを添えて待つ
- 着手するなら `CLAUDE.md` の「作業の流れ」1 から（Issue を確かめる → ブランチを作る）

## 5. 出し方

**長く書かない。** 申し送りを要約し直すと、読む場所が2つになる。出すのは:

1. **食い違い**（あれば。無ければ「申し送りと実物は合っている」の1行）
2. **いま動けるもの / 何待ちか**
3. **今日の一手の候補**（ユーザーが決める）

申し送りの全文が要るときは、ユーザーが読む。**写し直さない。**
