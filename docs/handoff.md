### GUI の起動
```
.venv/bin/python -m uvicorn web.main:app --host 0.0.0.0 --reload   # 起動
./open-gui.sh                                                       # ブラウザで開く
```
- **`--host 0.0.0.0` が要る。** 付けないと WSL の中だけで待ち、Windows 側のブラウザから入れない
- **`http://localhost:8000` は通らない**（Windows 10 では WSL の localhost 転送が効かない。#77 で確かめた）
- `./open-gui.sh` が、そのときの WSL の IP を調べてブラウザを開く。**IP は再起動すると変わる**ので、数字を文書に書かないこと
- サーバーが動いていない / `127.0.0.1` だけで待っているときは、`open-gui.sh` が開かずに理由を出して止まる
- `--host 0.0.0.0` は同じ LAN の他の機械からも見える。外のネットワークでは避ける

### 画面の確かめ方（CDP）
ヘッドレスの Chrome を CDP で動かすと、**実際にマウスを動かしてドラッグまで試せる**。#86 / #97 はこれで測った。

- ブラウザは `~/.cache/ms-playwright/chromium-*/chrome-linux*/chrome`。**版は勝手に入れ替わる**ので `ls` で探す
- 起動: `--headless=new --remote-debugging-port=9222 --no-sandbox --user-data-dir=<作業場所>`
- **`pkill -f "remote-debugging-port=9222"` を使わない。** パターンが自分のコマンド行にも当たってシェルごと死ぬ。`ps` で PID を拾って `kill` する
- 測るときは `python3 -m http.server` で配る。**キャッシュが効くので、冷えた状態を測るなら URL に `?v=<毎回違う値>` を付ける**

### 気をつけること
- リポジトリは公開。認証情報（`client_secret.json` / `token.json`）と音声は git の管理外だが、コミットする前に確かめる
- **`Closes #N` をバッククォートで囲むと GitHub が読まない。** 囲まずに書くか、マージした後に手で閉じる（day-3 で2回やった）
- **`ep*/00_logs/` には相談チャットの記録（`chat.json`）が入っている。** ログの掃除のつもりでフォルダごと消すと会話が消える
- **`ep*/00_logs/<工程>.log` は、その工程を動かすたびに上書きされる。** 失敗の様子を残したいときは、動かし直す前に控える
- **レビューの指摘や記録は、コードか実際の動きで確かめてから採用する。** day-3 で前提そのものが無い指摘が2件。day-4 で **#85 に残っていた「読み込み15秒」が、試験の作り方の問題**だと分かった
- **切り分ける前に原因を書かない。** day-4 で「markers を付けるとトラックが掴めなくなる」と書きかけたが、
  marker とは無関係で**尺の端で止まっていただけ**だった。marker 無しのものと並べて比べたら分かった
- **逆の結果が出たら、まず測り方を疑う。** 「6本で15秒、25本で2.7秒」という逆転が出て、条件を1つずつ外したら**同じファイルの使い回し**に行き着いた
- **名前を信じない。** `canplay` は「再生できる」であって「波形が描けた」ではない。復号前に `zoom()` を呼ぶと落ちる
- **結論は、測る前と後で変わる。** 案E'（鳴るが見えない）が有利に見えたが、marker の当たり判定を広げられると分かって五分に戻った
- **新しくできるようにした操作には、既存の操作が持っている守りを付け忘れやすい**（#58 で、端を掴んで縮めるときだけ最小長の確認が抜けていた）
- **対称なはずのものは、両方向を試す**（#58 で「音は1つだけ鳴る」を片方向しか確かめていなかった）
- **文書に数字を書くときも「動かしていないものは未確認と書く」**（#58 で「10分で数秒かかる」と断定し、測ったら 1.7秒だった）
- **「安全にしてある」と書いたら、それを守るテストまで書く**（#63。#58 と合わせて2回やった）
- **外部のライブラリやコマンドの振る舞いは、読んで決めつけず測る**（#63 の `acrossfade`、day-4 の multitrack）
- **`git add -A` を確かめずに使わない。** 文書だけの PR ではファイル名で指定する。使ったら `git diff --cached --name-only` を見てからコミットする（#78 で、ユーザーの作業を混ぜた）
- **「確かめたつもり」に気をつける。** WSL の中で `curl` が 200 を返しても、Windows 側から開ける確認にはならない（#75 → #77）
- **Issue を書く前に実機で測る。** #82・#85・#86 とも、動かしたら論点が消えたり増えたりした
- **「どう作るか」より先に「何を作るか」。** 番組の形が決まる前に設計を詰めると、論点の前提が浮く
- **Issue が重くなったら切り出す。** #86 が長くなったので倍率の話を #97 に、さらに #98 / #99 に分けた
- **一時領域（`/tmp/claude-1000/`）は消えることがある。** #86 / #97 の試験用の音声（1.7GB）もここにある。消えたら `ffmpeg` で作り直す
