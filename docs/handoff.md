### GUI の起動
```
.venv/bin/python -m uvicorn web.main:app --host 0.0.0.0 --reload   # 起動
./open-gui.sh                                                       # ブラウザで開く
```
- **`--host 0.0.0.0` が要る。** 付けないと WSL の中だけで待ち、Windows 側のブラウザから入れない
- **`http://localhost:8000` は通らない**（Windows 10 では WSL の localhost 転送が効かない。#77 で確かめた）
- `./open-gui.sh` が、そのときの WSL の IP を調べてブラウザを開く。**IP は再起動すると変わる**ので、数字を文書に書かないこと
- サーバーが動いていない / `127.0.0.1` だけで待っているときは、`open-gui.sh` が開かずに理由を出して止まる
- `--host 0.0.0.0` は同じ LAN の他の機械からも見える。外のネットワークでは避ける

### 画面の確かめ方（CDP）
ヘッドレスの Chrome を CDP で動かすと、**実際にマウスを動かしてドラッグまで試せる**。#86 / #97 はこれで測った。

- ブラウザは `~/.cache/ms-playwright/chromium-*/chrome-linux*/chrome`。**版は勝手に入れ替わる**ので `ls` で探す
- 起動: `--headless=new --remote-debugging-port=9222 --no-sandbox --user-data-dir=<作業場所>`
- **`pkill -f "remote-debugging-port=9222"` を使わない。** パターンが自分のコマンド行にも当たってシェルごと死ぬ。`ps` で PID を拾って `kill` する
- 測るときは `python3 -m http.server` で配る。**キャッシュが効くので、冷えた状態を測るなら URL に `?v=<毎回違う値>` を付ける**

- **「確かめた」と言う前に、何を測ったかを確かめる。** **手順ではなくテストにする。** `tests/test_hooks.py` と `tests/test_guards.py` がその形
- **`gh` が返す時刻は UTC。手元は日本時間で +9時間。** 引き算する前に揃える
- **Issue を起票するときに「直す手順」まで書いておく。** #112 でそのとおり進んで迷わなかった。**自分への申し送りになる**
- **数える前に決めない。** 許可リストのとき `fuser` を読み取り専用だと思い込んでいたが、**実物は全部 `-k`** だった
- **毎回走るものは、壊れ方を先に決める。** 始まるときの hook は `gh` が固まると 45秒かかっていた
- **「届いていない」と決めつける前に確かめる。** 相手のセッションの記録（`~/.claude/projects/<パス>/*.jsonl`）を検索すれば分かる
- Herdr の担当の名前は、Herdr 全体で重ならないようにする（フリーライフは `director` など、okuradi は `lead` と `impl-<番号>`）
- `herdr worktree remove` は、`--workspace` を省くと今いる場所が対象になる。必ず ID を指定する
- **同じ作業フォルダで Claude を2つ動かさない。** 分けるなら `git worktree`。作業に入る前に `git branch --show-current` を見る
- **件数は数え直す。引き算で出さない。** day-4 と day-5 で2回間違えた
- **画面の説明を書くときは、実物のボタン名を見る。** day-5 に「確定を押す」と書いたが、実物は「確認した」だった。
