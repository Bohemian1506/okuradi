## Docker を入れるか（結論: いまは入れない）
ユーザーから「Docker で環境を作ったほうがいいか」と質問があった。次の3点でひっかかるため、いまは入れないことにした。

1. **`claude -p`**: サブスクの枠で動かす決まりなので、コンテナに Claude Code とログイン情報を持ち込むことになる。いちばん壊れやすい所が増える
2. **GPU**: `build.py` は CUDA のライブラリを pip で入れて自前で読み込み、`LD_LIBRARY_PATH` をいじらずに済ませている（`build.py:125`）。Docker だと nvidia-container-toolkit の設定が要る
3. **ファイルの行き来**: 収録は Windows の OBS、中間ファイルは `ep01/` 以下。すでに境を1回またいでいて、もう1回増える。しかも工程の「古い」判定にファイルの更新日時を使い始めた

代わりに、入れ方を README にそろえることで、今日詰まった分は防げる。**Docker を覚えること自体が目的なら別の題材のほうが素直**、とも伝えた。

## エコーの調査（`audio-researcher`）
Issue #6 の「決める」とされていた3点に、実機で検証した答えが出た。ffmpeg 4.4.2 と `ep01` のコピーで確認。

| 論点 | 決定 | 理由 |
|---|---|---|
| 方式 | **`aecho` の多重タップ** | このビルドに `areverb` 等は無く、選択肢は `aecho` と `afir` だけ。`afir` は外部のインパルス応答（ライセンス確認と保管が要る）か、自作 IR の作り込みが要る。「新しい依存を増やさない」に合わない |
| 区間の指定 | **`atrim` で3分割 → 中間だけにエコー → `acrossfade` で繋ぐ** | `enable='between(t,…)'` は **`aecho`・`afir` とも非対応**（実際にエラーが出る）。`asendcmd` も同じ理由で使えない |
| 処理順 | **denoise → トリム → エコー → loudnorm** | エコーをトリムより前に入れると、響きの尾が切られるか、無音判定が狂う。loudnorm を最後にすれば天井（TP -1.5dB）に必ず収まる |
| 区間の時刻の基準 | **トリム後（`clean.wav`）の時刻** | `ep01` は生音源 59.58秒 → 整音後 57.11秒。内訳は先頭0.02秒・末尾2.45秒で、**どちらがどれだけ削れるかは回ごとにバラバラ**。トリム後を基準にすれば補正が要らず、画面の波形とも一致する |

- **繋ぎ目のプツッ音は実際に出る。** 波形の値を直接見て、境界で音量が約半分に急落することを確認。`acrossfade` を 15〜20ms 挟めば解消する（繋ぎ目1か所につき、その分だけ全体が短くなる）
- プリセットの案: 軽め = `aecho=0.85:0.6:40|70:0.25|0.15`、響く = `aecho=0.9:0.85:30|55|85|120|160|210:0.35|0.28|0.22|0.16|0.10|0.06`
- 試聴用の音は、入力側シーク（`-ss` を `-i` の前）で 0.056秒で作れる
- **音の「心地よさ」は聴いて決めるしかない**、と調査担当も書いている。実装したあとユーザーが聴いて調整する

## 申し送りの main の位置を、番号で書くのをやめた
- きっかけ: ユーザーの確認で、申し送りの `main は 0d1464c` が実際（`a4261f3`）と食い違っていることが分かった。**4回とも同じずれが出ていた**
- 原因: 申し送りはその PR の中で書くので、**書いた時点ではまだマージされておらず、マージした瞬間に main が1つ進む**。もう1コミット足して直しても、その直しがまた main を進めるので永久に追いつかない
- 直し方: ユーザーの判断は「コミットの番号を書くのをやめる」。最初は PR 番号に替えようとしたが、**書いてみて PR 番号でも同じずれが出ると気づいた**（「main は #73 をマージした所」も、次の PR で嘘になる）。**番号を書かず、「この申し送りを載せた PR をマージした所」とし、位置が要るときは `git log --oneline -1` を打つ**形にした

### 学んだこと
- **直し方を決める前に、その直し方が本当に直るかを一度書いてみる。** PR 番号に替える案は、口で言うと直りそうに聞こえたが、実際に書いたら同じ穴だった
- **文書に書く値は「番号が変わっても正しいこと」だけにする。** 追いかけ続けないと嘘になる値は、そもそも書かない
