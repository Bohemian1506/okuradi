## #80 feat: open-gui.sh を足す（#77 を閉じた）

### 原因が分かった
GUI を起動しても Windows のブラウザから開けなかった件。

| 住所 | 結果 |
|---|---|
| WSL の中から `127.0.0.1:8000` | 200 |
| WSL の IP `:8000` | **200（これで開ける）** |
| Windows から `localhost:8000` | **開けない** |

**Windows 10 では WSL の localhost 転送が効かない。** `--host 0.0.0.0` で待たせても同じだった。

`C:\Users\hiros\.wslconfig` に `networkingMode=mirrored` と書いてあるが、**これは Windows 11 22H2 以降専用で、Windows 10 では黙って無視される**（実際のネットワークは NAT のまま）。設定は書いてあるのに何も起きていない状態だった。

### IP が一晩で変わった
| いつ | IP |
|---|---|
| 2026-09-19 夜 | `172.31.77.123` |
| 2026-09-20 朝 | `172.31.73.115` |

前日に「申し送りに番号を書かない」と決めたばかりだったが、**同じことが IP でも起きると実地で分かった**。

### 決めたこと
| 論点 | 決定 | 理由 |
|---|---|---|
| 住所をどう固定するか | **`./open-gui.sh` を作る（案B-1。開くだけ）** | 打つとそのときの IP を調べてブラウザを開く。数字を覚えなくてよくなる |
| サーバーの起動も兼ねるか | **兼ねない** | 起動と画面を開くのを1つにすると、開かないときにどちらが原因か分からなくなる。**実際それで詰まった**（サーバーは動いていたのに住所が違っていた） |

### 確かめたこと
4つの場面を全部動かした。特に**昨日詰まった状況（`--host` を付け忘れて `127.0.0.1` だけで待っている）を言い当てる**ことを確かめた。

`--help` の表示範囲がずれて `set -uo pipefail` が余計に出ていたのも、打って気づいて直した。

### #79 mix 工程を新設する（親）
SE の重ね / BGM の敷き / 別 wav の連結 の3つを、**別々の機能として順に足すと破綻する**（それぞれが音声を切った貼ったするので、尺のズレで後から壊れる）。

`clean` と `transcribe` の間に `mix` を置き、**タイムライン定義を受け取って1本に組み立てる単一の工程**として設計する方針。論点を8つ書いた。

このリポジトリで具体的にどこが壊れるかを表にした。特に **`config.yml` の `echoes` は `trimmed.wav` の時刻で書く決まり**なので、mix が尺を変えるとこの基準ごと崩れる。

### #82 OP テーマソングの音量カーブ（#79 の子）
3つのうち**いちばん副作用の小さいもの**を最初のケースにする。音声を切らないので尺が変わらない。

**書く前に実機で測ったら、前提が崩れる発見があった。**

| 案 | 尺 | 下げた区間の音量 |
|---|---|---|
| `volume` の式（`eval=frame`） | **57.1149秒（変わらない）** | -29.3 → **-41.3 dB**（ぴったり -12dB） |
| `atrim` + `acrossfade`（**いまのエコーと同じやり方**） | **57.0749秒（0.04秒 縮む）** | -29.3 → -41.3 dB |

**いまのエコーのやり方は流用できない。** 継ぎ目ごとに `ECHO_CROSSFADE`（0.02秒）が重なって尺が縮む。
この機能を「最初のケース」にする理由は「尺が変わらないこと」だったので、**既存のやり方を持ってくると理由そのものが崩れる**。

## 午後: 番組の形を先に決めた

ユーザーの判断。「**まずラジオの形を決めて、それに合わせてアプリを改修する**」。
#79 / #82 は「どう作るか」の話で、「**何を作るか**」がまだ決まっていなかった。

### 決めたこと
| 論点 | 決定 |
|---|---|
| 収録の仕方 | **いまはコーナーごとに別録り。ただし一本録りに戻す可能性があるので、両方扱える形にする** |
| YouTube への出し方 | **30分の通しと、コーナーごとの切り抜きの両方** |
| OP・ED・ジングル | **全部入れる** |
| 切り抜きの範囲 | **回ごとに手で決める**（自動では決めない） |
| 動画の背景画像 | **全部同じ**（コーナーごとに変えない） |
| 下見・整音の単位 | **コーナーごと**（一本録りのときは1回で済む） |

**「通しと切り抜きの両方」が、mix 工程より大きい改修**になる。`meta` / `video` / `upload` が「1回につき1本」前提のため。

### 番組の仕様をもらって文書にした
ユーザーから番組そのものの仕様（番組名「アール放送局」、8コーナーの構成、OP の仕様、トーン）をもらい、`docs/program-spec.md` に起こした（のちに r-hoso へ移す）。

書きながら4つ気づいた。
- 構成の合計は **29:00**（「約30分」の中身）
- OP に「**曲の尺がトークの尺を支える**」という制約がある。曲が先に尽きるとトークが無音の上に乗る。#82 に無かったので足した
- `config.yml` の `series_rules` が**新しいコーナー名と一致していない**（「今**更**聞けない」と「今**さら**聞けない」で表記まで違う）
- もらった仕様と、直前の回答が1か所ずれていた（収録の仕方）。**仕様のほうで書き、報告した** → ユーザーの判断で「両方対応」に直した

## 午後: GUI をタイムライン編集に切り替える方向を決めた

ユーザーの言葉「**ラインごとにSEやBGM、トークなどわけて配置しそれぞれを編集できるようにした方が編集時は楽**」。

### 決めたこと
| 論点 | 決定 |
|---|---|
| レーンの本数 | 固定＋必要なら増やせる |
| トークを動かせるか | **自由に置ける** |
| 隙間ができたら | **無音のまま残す**（番組では間を意図的に空けたい）。ただし画面で目立たせる |
| いまの波形・エコー区間 | **トークのレーンに取り込む**（作り替え） |

### 調べたこと: `wavesurfer-multitrack` が使える
実際に動かして確かめた（5レーンを並べ、ドラッグし、音量カーブを出した）。

| 確かめたこと | 結果 |
|---|---|
| リポジトリに置けるか | **置ける。UMD・64KB・BSD-3-Clause**。wavesurfer 本体ごと同梱 |
| ドラッグ | **動いた。** `30秒 → 54.8秒`。`start-position-change` が逐次飛ぶ |
| 音量カーブ | **出来合いで付いてくる。** `envelope` の点をドラッグで動かせる |
| 制限 | **1レーン = 音源1つ。** SE が10個あれば10レーン |
| 読み込み | 57秒の音 × 5レーンで**約15秒** |

**#82（OP の音量カーブ）の UI を、自分で作る必要がなくなった。** しかも `envelope` の点は `{time, volume}` の折れ線で、#82 に書いた案C とそのまま一致する。

### 覆ったこと
**#79 の論点2（mix を `clean` と `transcribe` の間に置く理由）が覆った。**
トークを自由に置けるなら、**文字起こしはクリップごとに持ち、位置で足し算する**のが自然。動かしたとき変わるのは足す数だけなので、mix が `transcribe` より前である必要がない。
