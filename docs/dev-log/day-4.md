## #80 feat: open-gui.sh を足す（#77 を閉じた）

### 原因が分かった
GUI を起動しても Windows のブラウザから開けなかった件。

| 住所 | 結果 |
|---|---|
| WSL の中から `127.0.0.1:8000` | 200 |
| WSL の IP `:8000` | **200（これで開ける）** |
| Windows から `localhost:8000` | **開けない** |

**Windows 10 では WSL の localhost 転送が効かない。** `--host 0.0.0.0` で待たせても同じだった。

`C:\Users\hiros\.wslconfig` に `networkingMode=mirrored` と書いてあるが、**これは Windows 11 22H2 以降専用で、Windows 10 では黙って無視される**（実際のネットワークは NAT のまま）。設定は書いてあるのに何も起きていない状態だった。

### IP が一晩で変わった
| いつ | IP |
|---|---|
| 2026-09-19 夜 | `172.31.77.123` |
| 2026-09-20 朝 | `172.31.73.115` |

前日に「申し送りに番号を書かない」と決めたばかりだったが、**同じことが IP でも起きると実地で分かった**。

### 決めたこと
| 論点 | 決定 | 理由 |
|---|---|---|
| 住所をどう固定するか | **`./open-gui.sh` を作る（案B-1。開くだけ）** | 打つとそのときの IP を調べてブラウザを開く。数字を覚えなくてよくなる |
| サーバーの起動も兼ねるか | **兼ねない** | 起動と画面を開くのを1つにすると、開かないときにどちらが原因か分からなくなる。**実際それで詰まった**（サーバーは動いていたのに住所が違っていた） |

### #79 mix 工程を新設する（親）
SE の重ね / BGM の敷き / 別 wav の連結 の3つを、**別々の機能として順に足すと破綻する**（それぞれが音声を切った貼ったするので、尺のズレで後から壊れる）。

`clean` と `transcribe` の間に `mix` を置き、**タイムライン定義を受け取って1本に組み立てる単一の工程**として設計する方針。論点を8つ書いた。

### #82 OP テーマソングの音量カーブ（#79 の子）
3つのうち**いちばん副作用の小さいもの**を最初のケースにする。音声を切らないので尺が変わらない。

**書く前に実機で測ったら、前提が崩れる発見があった。**

| 案 | 尺 | 下げた区間の音量 |
|---|---|---|
| `volume` の式（`eval=frame`） | **57.1149秒（変わらない）** | -29.3 → **-41.3 dB**（ぴったり -12dB） |
| `atrim` + `acrossfade`（**いまのエコーと同じやり方**） | **57.0749秒（0.04秒 縮む）** | -29.3 → -41.3 dB |

**いまのエコーのやり方は流用できない。** 継ぎ目ごとに `ECHO_CROSSFADE`（0.02秒）が重なって尺が縮む。
この機能を「最初のケース」にする理由は「尺が変わらないこと」だったので、**既存のやり方を持ってくると理由そのものが崩れる**。

### 案E の読みは当たっていた

- **markers の `drag` は既定で有効** → そのとおり。10秒 → 15.92秒 に動かせて `region-updated` で拾えた

### 読みに無かったこと（4つ）
1. **クリップを「今ある全体の尺」の外へは出せない。** 最後のコーナーを後ろへずらせない
2. **読み込みは速い。#85 の「15秒」は試験の作り方の問題だった。** 同じ wav を5レーンで使い回したための数字で、

3. **`canplay` は波形が描けた合図ではない。** 尺が分かった時点で飛ぶ（25本で0.2秒。波形がそろうのは2.7秒）
4. **multitrack は wavesurfer を丸ごと同梱している**（`^7.6.3`）。`web/static/vendor/` は 7.8.6 なので**2つ同居する**。
   regions も別物で、7.8.6 にある `region-update`（ドラッグ中）が multitrack 側には無い

### 倍率を測って、結論がひっくり返った
案E' には弱点があった。**30分を1画面に収めると、SE 0.5秒の幅は 0.28px** で、見えも掴めもしない。
逆に **marker はどの倍率でも 2px** なので、そこだけ強い。

ユーザーの判断で倍率を実測した（音源49本の実物大）。

| 倍率 | SE 0.5秒の幅 | 画面に映る長さ |
|---|---|---|
| 0.64px/秒（全体） | 0.28px | 35.4分 |
| 10px/秒 | 5px | 2.3分 |
| 20px/秒 | 10px | 1.1分 |

**掴める範囲はクリップの幅の半分だけで、当たり判定の余白は無い。** 5px のずれを許すには 20px/秒 が要り、
そのとき画面に映るのは 1.1分だけ。

そして**結論が変わった**。**marker の当たり判定は CSS で広げられた**（2px → 14px）。
`app.js` の `paintWave()` が既に使っている「shadow DOM へ `<style>` を差し込む」やり方で、時刻をずらさずに広げられる。
縦書きラベルの読みにくさも同時に消えた。

**注意**: marker の `part` は `region` ではなく **`marker`**。`app.js` の `[part~="region"]` では当たらない。

と書いているのを、r-hoso の画面を読んで見つけた。ユーザーの指示で調べた。

### 見つけたもの
**併用ではなく、片方の弱点を消す形だった。**

```css
.se-clip { min-width: 14px !important; }
```

SE は音源のまま置き（案E'）、クリップに最低幅を与える。それだけ。
**marker の当たり判定を 2px → 14px に広げたのと同じ手を、音源クリップに使った。**

| 確かめたこと（倍率 0.64px/秒＝35分を1画面） | 結果 |
|---|---|
| 幅 | 0.32px → **14px** |
| 掴めるか | 狙いを5px外しても**掴める** |
| 時刻が狂わないか | **狂わない**（340秒 → 496.2秒。100px ÷ 0.64 = 156.25秒。計算どおり） |
| 開始位置 | **ずれない**（箱は右へ伸びるので、左端が本当の開始時刻） |
| 音 | **鳴る**（本物の音源トラックのまま） |
| 土台トラック | **要らない**。読み込みは 3.7〜4.0秒のまま |

拡大すれば本来の幅に戻る（28px/秒 が境目。50px/秒 → 25px）。
見た目は**細い線**にできる（14px の箱に見えると 22秒の音と誤解されるため）。

**この CSS は shadow DOM の外に当たる**ので、`paintWave()` のような差し込みは要らない。
marker を広げるときは中に差し込む必要があったが、こちらは普通のスタイルシートで届く。

### 争点が消えた
| | 案E（marker） | 案E'（音源） | **案E' + 最低幅** |
|---|---|---|---|
| 試聴で鳴る | ✗ | ○ | **○** |
| 全体表示で見える | ○ | ✗ | **○** |
| 掴むのに拡大が要る | 要らない | 要る（1.1分の窓） | **要らない** |
| 読み込み | 18.6秒 | 3.7〜4.0秒 | **3.7〜4.0秒** |

**marker を使う理由が無くなった。** 利点は「どの倍率でも見える」の1点だったが、最低幅なら音源のまま同じことができる。

残る限界は、全体表示で 14px ＝ 約22秒ぶんなので、**SE 同士が近いと箱が重なる**こと。
ただし先の SE は重なっていない左側が掴める範囲として残る（10秒差で 6.4px。実際に掴めることを確認）。
**近すぎるときは拡大すれば解決する。**

### この Issue が長く止まっていた理由と、解けた順番
1. **SE を何個使うか**が決まらないと、レーン数が数えられなかった（番組側の話）
2. 番組側が「**BGM は1コーナー1曲**」と決めて、上限が25本で固定された
3. それでも SE と合いの手は「回数を決めない」ままだったが、**重ねられる**と分かって数の問題が消えた
4. 番組側が「**SE と合いの手は必ずずらす**」と決めて、行3 が1行で済むことが確定した
5. 最後に残った「鳴る/見える」の争点が、**最低幅**で消えた

**5段階のうち、番組側の決定が3つ。** 「番組の決定がアプリの作りを決める」がそのまま効いた形。

### 落とした案と理由
| 案 | 落とした理由 |
|---|---|
| A: レーンが増えるに任せる | 25本でも画面に収まらず、SE と合いの手は数が決まらない |
| B: 種類ごとにまとめて見せる | 重ねるだけで足りるので、外側を自前で描く必要が無い |
| C: SE を印にする | 鳴らない |
| D: 自前で作る | ドラッグ・音量カーブ・時間軸・同期再生を全部書くことになる |
| E: SE を marker で置く | 鳴らない。全尺ぶんの無音の土台が要る（読み込み18.6秒） |
