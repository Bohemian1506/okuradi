## #80 feat: open-gui.sh を足す（#77 を閉じた）

### 原因が分かった
GUI を起動しても Windows のブラウザから開けなかった件。

| 住所 | 結果 |
|---|---|
| WSL の中から `127.0.0.1:8000` | 200 |
| WSL の IP `:8000` | **200（これで開ける）** |
| Windows から `localhost:8000` | **開けない** |

**Windows 10 では WSL の localhost 転送が効かない。** `--host 0.0.0.0` で待たせても同じだった。

`C:\Users\hiros\.wslconfig` に `networkingMode=mirrored` と書いてあるが、**これは Windows 11 22H2 以降専用で、Windows 10 では黙って無視される**（実際のネットワークは NAT のまま）。設定は書いてあるのに何も起きていない状態だった。

### IP が一晩で変わった
| いつ | IP |
|---|---|
| 2026-09-19 夜 | `172.31.77.123` |
| 2026-09-20 朝 | `172.31.73.115` |

前日に「申し送りに番号を書かない」と決めたばかりだったが、**同じことが IP でも起きると実地で分かった**。

### 決めたこと
| 論点 | 決定 | 理由 |
|---|---|---|
| 住所をどう固定するか | **`./open-gui.sh` を作る（案B-1。開くだけ）** | 打つとそのときの IP を調べてブラウザを開く。数字を覚えなくてよくなる |
| サーバーの起動も兼ねるか | **兼ねない** | 起動と画面を開くのを1つにすると、開かないときにどちらが原因か分からなくなる。**実際それで詰まった**（サーバーは動いていたのに住所が違っていた） |

### 確かめたこと
4つの場面を全部動かした。特に**昨日詰まった状況（`--host` を付け忘れて `127.0.0.1` だけで待っている）を言い当てる**ことを確かめた。

`--help` の表示範囲がずれて `set -uo pipefail` が余計に出ていたのも、打って気づいて直した。

### #79 mix 工程を新設する（親）
SE の重ね / BGM の敷き / 別 wav の連結 の3つを、**別々の機能として順に足すと破綻する**（それぞれが音声を切った貼ったするので、尺のズレで後から壊れる）。

`clean` と `transcribe` の間に `mix` を置き、**タイムライン定義を受け取って1本に組み立てる単一の工程**として設計する方針。論点を8つ書いた。

このリポジトリで具体的にどこが壊れるかを表にした。特に **`config.yml` の `echoes` は `trimmed.wav` の時刻で書く決まり**なので、mix が尺を変えるとこの基準ごと崩れる。

### #82 OP テーマソングの音量カーブ（#79 の子）
3つのうち**いちばん副作用の小さいもの**を最初のケースにする。音声を切らないので尺が変わらない。

**書く前に実機で測ったら、前提が崩れる発見があった。**

| 案 | 尺 | 下げた区間の音量 |
|---|---|---|
| `volume` の式（`eval=frame`） | **57.1149秒（変わらない）** | -29.3 → **-41.3 dB**（ぴったり -12dB） |
| `atrim` + `acrossfade`（**いまのエコーと同じやり方**） | **57.0749秒（0.04秒 縮む）** | -29.3 → -41.3 dB |

**いまのエコーのやり方は流用できない。** 継ぎ目ごとに `ECHO_CROSSFADE`（0.02秒）が重なって尺が縮む。
この機能を「最初のケース」にする理由は「尺が変わらないこと」だったので、**既存のやり方を持ってくると理由そのものが崩れる**。
