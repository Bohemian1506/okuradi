## #10 chore: 担当のサブエージェント・Herdr・議事録の体制を作る
- きっかけ: 「フリーライフや weight_dialy のように、複数のサブエージェントを各種の担当として配置して作業する環境を作りたい」「Herdr を試してみたい」
- 検討したこと
  - weight_dialy はサブエージェント（1つの会話の中から呼ぶ担当）、フリーライフは Herdr で Claude を何人も常駐させる形。okuradi は1人で作る小さな Python のアプリなので、フリーライフの仕組み（起動スクリプト、自動中継）は写さず、サブエージェントを基本にして、並行作業のときだけ Herdr で Claude を増やす形にした
  - 「harder」は、フリーライフで使っている端末アプリの **Herdr** のことだった
  - weight_dialy の開発記録と memory から、ユーザーの考え方・進め方を分析し、`CLAUDE.md` に反映した（勝手に決めない、確かめてから採用する、など）
- 決めたこと

  | 論点 | 決定 | 理由・メモ |
  |---|---|---|
  | 担当 | 実装2（処理側・画面）、テスト、調査、レビュー4 | |
  | レビュー担当 | **デザイン視点と、アプリ利用者の視点を分ける** | ユーザーの要望。code / scope / design / user の4人 |
  | Herdr | **今すぐ使い始める** | 使い方は `docs/herdr.md` |
  | レビューのかけ方 | **毎回全員ではなく、必要なときに必要な担当を呼ぶ** | 「毎回4人はいらなく、必要なときに都度呼び出す感じにしたい」。`/review-team` が変更の中身から担当を選び、理由を示す。担当を名指しで呼ぶこともできる |
  | 議事録 | **PR をマージするたびに、すぐ議事録の PR を作る** | 「なぜその PR に至ったのかという変遷の履歴を新鮮なうちに撮りたい」ので、手間はかかっても都度やる。作業の PR に同梱する案は選ばなかった |
  | 完了の基準 | **変えた工程を、実際の音声で通したら完了** | 毎回すべての工程を通す案、画面ができた区切りだけ全部通す案は選ばなかった |
  | コマンドでの制作 | **GUI が完成するまでも、`build.py` のコマンドで番組を作れる状態を保つ** | GUI ができるまでの間も番組を出し続けるため。GUI で使わない `cut`・`upload` も残す |
  | main の守り | **リポジトリを公開して、GitHub 側でも main への直接 push を禁止する** | 手元の仕組みは `--no-verify` などで抜けられる。非公開のままだと GitHub Pro が要る。「わざわざ見に来る人はいない」ので公開を選んだ。コミットのメールアドレスは、ほかの公開リポジトリですでに公開されていることを確認した |

- やったこと
  - サブエージェント8人、`/review-team`、main への push を止める hook（Claude 側・git 側）、`CLAUDE.md`、`docs/herdr.md`、議事録（day-1・day-2）
  - リポジトリの外: `herdr integration install claude`、`~/.claude/skills/herdr/SKILL.md`、`git config core.hooksPath .githooks`
  - 4人のレビューにかけ、指摘を反映した（hook の誤検知・見逃し、Herdr の片付け手順の危険、担当の定義のずれ など）
- 困ったこと
  - hook が、コミットメッセージの中の「main」に反応して止めた（改行を区切りにしていなかった）。さらにレビューで、引用符の中の文字にも反応すること、`git -C <パス> push` などを見逃すことが分かり、書き直した
  - リポジトリを公開する操作は、Claude Code の安全機能で止められた → ユーザーが自分で `gh repo edit --visibility public` を実行した
- マージ前にしたこと（PR の差分の外）
  - リポジトリを公開した
  - GitHub 側で main を守る設定を入れた: 直接 push の禁止（PR からのマージだけ）、管理者にも適用、承認は不要、強制 push・削除の禁止。設定後も PR #10 が自分でマージできることを確かめてからマージした
- 学んだこと
  - Herdr のペインの ID は閉じると二度と使われない。担当は名前（`lead`、`impl-5` など）で呼ぶ
  - Herdr の作業フォルダには、git の管理外の音声・途中のファイルが入らない。並行で実装するときは、試し方を先に決めておく
  - `herdr worktree remove` は、`--workspace` を省くと今いる場所が対象になる
  - 非公開リポジトリの branch protection は、無料プランでは使えない

## #13 chore: Herdr と Claude を1つのコマンドで起動する start.sh
- きっかけ: 「フリーライフのように、カスタムコマンドで Herdr と Claude の起動などを一手にできるようにしたい」。続けて「フリーライフと同時に起動できるようにしたい」（Issue #12）
- 検討したこと
  - フリーライフの `start.sh`（役割ごとの作業フォルダ、自動中継、配置の検査など）は写さず、okuradi に要る分（サーバー・ワークスペース・`lead`・画面の切り替え）だけにした
  - 手軽に呼ぶ方法として、`okuradi` コマンド（`~/.local/bin` へのリンク）と WezTerm の F12 のメニューを出した → **F12 のメニュー**を選んだ
  - フリーライフとの同時起動: Herdr は1つだけ動き、その中にワークスペースが並ぶので、もともと同時に使える。問題は PC を再起動した後の起動の手間だけだった
  - 同時起動の仕組みの置き場所（okuradi の `start.sh` / ホームの別スクリプト / フリーライフ側）を確認した。ユーザーは「F12 でフリーライフか okuradi かを選んで分けたい」「フリーライフ側でやったときに okuradi もワークスペースに入れるには、フリーライフ側をいじる必要があるか」と質問 → フリーライフのリポジトリは変えず、WezTerm のメニューと okuradi の `start.sh` だけで実現できると回答
- 決めたこと

  | 論点 | 決定 | 理由・メモ |
  |---|---|---|
  | 起動の入口 | WezTerm の F12 のメニュー | フリーライフと同じ使い方 |
  | メニューの分け方 | 「herdr: okuradi」「herdr: フリーライフ資料」を分けたまま、「herdr: okuradi + フリーライフ」を足す | 開くものを選びたい |
  | フリーライフのメニューで okuradi の Claude も起動するか | **起動する** | 「しばらくは並行作業を行うと思うので」 |
  | フリーライフ側の変更 | しない | okuradi の `start.sh` が、フリーライフのワークスペースの中でフリーライフの `start.sh` を実行する |

- やったこと
  - `start.sh`: `-c`（前回の続き）、`--with-freelife`（フリーライフも起動）、`--open-freelife`（フリーライフの画面を開く）、`--no-attach`（用意だけ）
  - WezTerm の設定（リポジトリの外）: F12 のメニューを3つに
  - `docs/herdr.md`、`CLAUDE.md` の起動手順を更新
  - code-reviewer と user-reviewer にかけ、指摘を反映した（サーバーの状態の判定、やり直しの条件、失敗したときの案内、状態の日本語表示 など）
  - ユーザーが F12 から「herdr: okuradi」「herdr: フリーライフ資料」を開けることを確かめてからマージした
- 困ったこと
  - 作ったばかりのペインの準備ができる前に探して、ペインが余計に増えた → 準備を待つようにした
  - 最初は `--no-attach` でしか試せず、画面の切り替えはユーザーに確かめてもらった
  - PC を再起動した後、フリーライフのメニューから開くと、先に okuradi が Herdr を起動するため、フリーライフのワークスペースが自動で作られないおそれがあった → `--open-freelife` でワークスペースも用意するようにした
- 学んだこと
  - Herdr の `agent start` は、使用中のペインだと `agent_pane_busy` を返す
  - Herdr の中で動くスクリプトには `HERDR_ENV=1` が入る。`herdr pane run` で別のペインにコマンドを送れば、そのペインの中で実行される
  - jq で `label` を `{label}` のように省略して書くと、文法エラーになる（`label` は jq の予約語）
- 未確認: フリーライフが止まっている状態から「herdr: okuradi + フリーライフ」で起動するところ（次に PC を再起動したときに確かめる）
