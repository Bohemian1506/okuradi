## 決めたこと
### 画面と部品（#2）
| 論点 | 決定 |
|---|---|
| 画面の構成 | 3画面（回の設定 / 収録〜整音 / 仕上げ）をタブで切り替える |
| 相談チャット | どの画面からでも開ける右側のパネル |
| 「古い」の状態 | 最初の版に入れる（前の工程をやり直したら、後ろの工程を作り直しが要ると表示） |
| 中止ボタン | 入れる |
| 整音結果の確認 | 「確認した」ボタンは置くが、押さなくても次に進める |
| 文字起こしの間違い | 確定版をユーザーが聴きながら直せるようにする。直したものをタイトル・概要欄・章の生成に使う。**字幕ファイルは作らない**（「字幕」の範囲を確認したうえでの判断） |

### 作業の体制
| 論点 | 決定 | 理由・メモ |
|---|---|---|
| 担当の分け方 | weight_dialy と同じくサブエージェントで分担する | 実装2（処理側・画面）、テスト、調査、レビュー4 |
| レビュー担当 | **デザイン視点と、アプリ利用者の視点を分ける** | ユーザーの要望。code / scope / design / user の4人 |
| Herdr | **今すぐ使い始める** | Issue を並行で進めるときに Claude を増やす。使い方は `docs/herdr.md` |
| 議事録 | weight_dialy の dev-log と同じく、マージ後に day-N で残す | 後から見返すため。weight_dialy 後半の反省から、冒頭で要点が分かる軽い形にする |

## 困ったこと
- 「harder」がどのツールか分からなかった → フリーライフの運用資料から、端末アプリの **Herdr** だと分かった
- `/design`（Claude Design のキャンバス）を引数なしで試した → ユーザーの試し打ちだったので、何もしなかった

## 学んだこと
- Herdr のペインの ID は閉じると二度と使われない。担当は名前（`lead`、`impl-5` など）で呼ぶ
- Herdr の作業フォルダ（worktree）には、git の管理外の音声・途中のファイルが入らない。並行で実装するときは、試し方を先に決めておく
