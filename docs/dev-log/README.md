# 開発記録（議事録）

PR ごとに「なぜその PR に至ったか」の経緯を、マージ直後の新鮮なうちに残す。後から「なぜこうしたか」を見返すための記録。

## ファイルの付け方
- `day-N.md`。N は **作業した日の連番**（カレンダーの日付ではない。作業しなかった日は数えない）
- 同じ日に PR が複数あれば、その日の `day-N.md` に追記していく
- day-1 = 2026-09-14

## いつ・どう書くか
1. **PR をマージしたら、すぐに書く**（次の作業に入る前）
2. `docs/day-N-<PR番号>` のようなブランチを作り、`day-N.md` に追記する（無ければ作る）
3. `docs: day-N 議事録（#PR番号）` という PR にしてマージする
- 議事録だけの PR には、レビュー担当は呼ばなくてよい
- 誤字直しなど、経緯を残すほどでない PR は省いてよい

## 書くこと
日の冒頭に、その日の要点を数行で書く。PR ごとに「経緯」の節を足していく。

### 冒頭のまとめは、区切るたびに測り直す
**前の版から写さない。** day-4 に、朝書いた「実装らしい実装はしていない日」をそのまま残し、
夕方までに729行書いたのに直さなかった。

```
docs/dev-log/day-stats.sh          # 今日
docs/dev-log/day-stats.sh 2026-09-20
```

マージした PR の数、**文書とそれ以外に分けた行数**、新しく足したファイルが出る。
**その数字を冒頭に書く。**
書くことがない見出しは省いてよい。

```
# Day N（YYYY-MM-DD）<その日の要約>

<その日の要点を数行>
```
