## #206 fix: lead を起動して名前が付いたあとで /始め を送る（#205）

### きっかけ
ユーザー: 「ちょっと緊急で確認して欲しいのですがF12でうまく起動しませんでした。今は手動でclaudeを起動してます。」

調べると、**Claude は起動していて `/始め` も走っていた**（08:46 に作業のペインができていた）。**ただ Herdr で `lead` の名前が付いていなかった。**
2回目の F12 で `start.sh` が `lead` を見つけられず、**別のペインにもう1つ Claude を立てた**。手で起動した分と合わせて、**okuradi のフォルダで Claude が3つ**動いていた。

### 原因
`herdr agent start` は「**起動して、入力待ちになった**」ことを確かめてから成功を返し、名前を付ける（既定で30秒待つ）。
`/始め` を起動の引数で渡すと、**Claude は起動した直後から作業を始めて入力待ちにならない**。30秒で待ち切れずに失敗扱いになった。

根拠（Herdr のログ）:
- `/始め` を渡した2回とも、`agent.start` の**ちょうど30秒後**に `cli:agent:start:timeout`
- 同じ時刻に引数なしで起動したフリーライフの3つ（`director` など）には名前が付いていた

### 検討したこと
| 案 | 中身 | |
|---|---|---|
| **A** | 何も渡さずに起動し、名前が付いたあとで `herdr agent prompt lead /始め` で送る | **採った** |
| B | #198 を元に戻す | 朝に一言打つ手間が戻る |
| C | 待つ時間を延ばす | `/始め` が終わって入力待ちになるまでの時間は毎朝違うので、確実にならない |

### 決めたこと
- **A**（ユーザーの判断: 「Aで直して、Issueも立てて。herdr側の二つを閉じましょう。」）
- 確認の画面で止まったとき（`agent_not_ready`）は送らない（送ると答えとして入る）。「答えたあと /始め を打って」と出す（仮置き）
- 送れなかったときは止めない（`lead` は動いているため）。理由を出して「/始め を打って」と出す（仮置き）

### `run` タブ
- ユーザーの問い: 「現在この画面にrunというタブがありますがこれ何用でしたっけ？」
- 9/17 の `start.sh` からある。**GUI のサーバー・ログ・長い処理を動かしておく場所**（`docs/herdr.md` の図）。
  **#193 の作業のペイン（GUIログ）ができてから、役目がほぼ無くなっている**（今朝も空のシェルだけ）
- ユーザーの案: 「runタブを残して実際に動いてるときは独立したウインドウに移し、2枚の画面で管理したい」
- **Herdr にタブを別のウインドウへ切り出す機能は無い**（0.8.2 の `herdr tab` は list / create / get / focus / rename / close）
- 画面（クライアント）は1つのサーバーに何枚もつなげるので、2枚目の WezTerm で `herdr` を開いて試した。
  **2枚目で `run` に切り替えると、1枚目も切り替わった。** 見ているタブは画面どうしで共有される（2026-09-26・ユーザーが手で試した）
  - 試すときは F12 を使わなかった。`start.sh` は最後に画面を `lead` に合わせるので、どちらが切り替えたか見分けがつかなくなる
- 残る案は「Herdr の別セッション（`herdr --session run`）」か「Herdr を使わない普通のウインドウ」。
  **どちらも、この Claude からそこのログを読めなくなる**（Herdr の窓口 `.sock` がセッションごとに別。別の窓口に届く方法は調べていない）
- **いまの形のまま**（ユーザーの判断: 「今の形でいきましょう。」）。GUI のサーバーは作業のペインの GUIログで立てる。`run` タブも触らない

### 学んだこと
