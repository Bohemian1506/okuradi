### 困ったこと / 学んだこと

**同じ形の取り違えを、1日で2回やった。どちらも「見る場所を間違えた」。**

| | 何を間違えたか |
|---|---|
| 1 | 手順書の「**保存する**」が画面に無いと思い、「保存」に直しかけた。**実物は、区間を選んだ直後だけ「保存する」**（`app.js` の `dirty ? "保存する" : "保存"`）。整音の直後に見たので、保存済みの状態の「保存」しか見えていなかった |
| 2 | 「整音の結果が**古い**に変わる」が起きないと思った。**見るのはダイヤルではなく整音のパネル**。ダイヤルの判定（`step_states`）は音源の更新日時しか見ず、パネル（`_why_stale`）はエコーの変更も見る。**「古い」が2つある** |

**どちらも、採用する前にコードと実物で裏を取ったから止まった。** 1つ目は `grep` で `app.js` の
`dirty ? "保存する" : "保存"` に当たって気づき、実物でも確かめ直した（ドラッグ前は「保存」、ドラッグ後は「保存する」）。

**day-5 の「測る場所を間違えない」と同じ形で、これが3回目。**
前の2回は「別ブランチの件数を測った」「全角コロンに grep が当たらなかった」。
**今回は「画面の別の場所を見た」「別の状態のときに見た」。**
共通しているのは、**測る前に「どこを・どの状態で見るか」を決めていない**こと。

もう1つ。**レビュー担当を呼んだ判断はよかった。** 5件のうち2件は**自分が今日書いた文**への指摘で、
とくに「開き直しても残る」は**嘘ではないが読み手を間違った方へ連れていく**書き方だった。自分では気づけなかった。
