## #145 timeline.yml の読み書きと、錨から番組の時刻を出す計算（#144）

**この日はじめてコードを書いた。** ここまでは決定と文書だけだった。

    **データの形が固まる前にそこを触ると、どちらのせいで壊れたか分からなくなる**

### 決めたこと: 錨（いかり）で持つ

**保存するのは「どのクリップの、先頭から何秒か」だけ。番組の先頭からの秒数は計算して出す。**

絶対秒で持つと、**コーナーを録り直すたびに後ろ全部の数字を書き直す**ことになる（#79 本文の「避けたい」形）。
もう1つ、絶対秒だけでは **「その SE はコーナーの12秒の所に付いていたのか、番組の8分20秒の所に付いていたのか」が
区別できない**ので、詰め直しの正解が決まらない。

実測値で確かめた（収録音 57.114938秒 / ずんだもん 473.308秒）。**収録を10秒伸ばすと、後ろのクリップも、
そこに付いた SE も、きっかり10秒動く。**

### 同じ日のうちに決め直した

**最初の決定に穴があった。** レビューで見つかった。

`cuts` と `echoes` を別々の並びで持つ形にしていたが、**この2つは時刻の原点が違う。**
工程が `scan → cut → clean` で、`step_cut` は生音を読み、`trimmed.wav` はカットの後に作られる
（`build.py:252` / `build.py:432`）。**カットは長さも変える**ので、
README の「時刻の基準は、その編集で長さが変わらない音に置く」がカットだけ当てはまらない。

**ユーザーの案で、Premiere などと同じ分け方にした。**

| | 何が入るか | 何で数えるか |
|---|---|---|
| **素材に対する指示** | カット・エコー（`edits` という**1つの並び**に `kind` を付ける） | **生音の時刻** |
| **出来上がりに対する位置** | クリップの配置・SE・文字起こし・章 | **出来上がった音の時刻** |
