# GUI の部品

`docs/features.md` で決めた最初の版の「必須」の17機能をもとに、画面を作る部品を洗い出す。
ここで決めた部品を Claude Design でデザインする（#4）。
できたデザインの見本は `docs/design/`（雰囲気は案B トランジスタ）。渡した指示文は `docs/design-prompt.md`。

## 前提

- 工程は `build.py` のものを使う。ただし GUI の流れでは次の2点が今と違う。
  - ~~**途中のカットはしない**（決定 3）。`cut` 工程は使わず、`clean` で前後の無音トリムだけする。~~
    **決定3は取り下げた**（2026-09-22・`docs/features.md`）。**`cut` を GUI に出す。**
    **ただし、まだ実装していない。** いまの画面は `cut` を使っていない。
  - **アップロードはしない**。YouTube には、コピーしたタイトルなどを貼って手で上げる。
- GUI で見せる工程は7つ（2026-09-26 に `mix` を足した・#85 の4段目。それまでは6つ）。

```
音源 -> 下見 -> 整音 -> 曲を重ねる -> 文字起こし -> メタデータ -> 動画
         scan    clean   mix          transcribe    meta           video
```

- `mix` は `timeline.yml` の BGM・SE を `clean.wav` の上に重ねる。**文字起こしは喋りだけの `clean.wav` を使い、動画は `mix.wav` を使う**
- `mix` の画面（「ミックスして聴く」）の部品は、まだ番号を振っていない（仮置き）

## 状態の呼び方

部品の状態は、できるだけ次の言葉にそろえる。

| 状態 | 意味 |
|---|---|
| 未実行 | 前の工程が終わっていないので、まだ実行できない |
| 実行できる | 前の工程が終わっていて、実行できる |
| 処理中 | 実行している。経過時間を出す |
| 完了 | 結果がある |
| エラー | 失敗した。エラー文を出し、ログを開ける |
| 中止 | 途中で止めた。結果は前のまま |
| 古い | 結果はあるが、前の工程をやり直したので作り直しが要る（例: 録り直したのに動画が前のまま） |

## 画面の構成

画面は3つ。回を選ぶ・工程を見る・相談する・ログを見る部分は、どの画面にも共通で出す。

```
+------------+---------------------------------------------+------------+
| 回セレクタ |  工程ステッパー                              |            |
|            +---------------------------------------------+  相談      |
|  ep01      |                                             |  チャット  |
|  ep02 <    |   メイン（3画面をタブで切り替える）          |            |
|            |     1. 回の設定                             | （開閉）   |
|  + 新しい回|     2. 収録〜整音                           |            |
|            |     3. 仕上げ                               |            |
|            +---------------------------------------------+            |
|            |  処理状況バー / ログ（開閉）                 |            |
+------------+---------------------------------------------+------------+
```

| 画面 | 置く部品 | 担当 Issue |
|---|---|---|
| 共通の枠 | 回セレクタ / 新しい回ダイアログ / 工程ステッパー / 処理状況バーとログ / 相談チャット / 改善メモの下書きダイアログ | #5, #8 |
| 1. 回の設定 | コーナー・テーマ編集 | #5 |
| 2. 収録〜整音 | 音源の追加 / 収録ファイルカード / 音声プレーヤー / 文字起こしリスト / 波形ビュー / エコー区間リスト / 整音結果パネル / 工程実行ボタン | #6 |
| 3. 仕上げ | 文字起こしリスト / 音声プレーヤー / メタデータエディタ / 保留チェック / コピーボタン / 動画プレビュー / 工程実行ボタン | #7 |

## 部品の一覧

### 共通の枠

#### 1. 回セレクタ
- 役割: 回の一覧を出し、作業する回を選ぶ。「新しい回」ボタンを持つ。
- 表示: 回の番号、テーマ、進み具合（6工程のうちいくつ終わったか）
- 状態: 回がない（「新しい回」だけを出す） / 通常 / 選択中
- 機能: 回の一覧と選択

#### 2. 新しい回ダイアログ
- 役割: 新しい回のフォルダを作る。番号は最後の回の次を自動で入れる。
- 入力: 回の番号、コーナー、テーマ
- 状態: 入力中 / 作成中 / エラー（同じ番号がすでにある など）
- 機能: 新しい回を作る

#### 3. 工程ステッパー
- 役割: 6工程の状態を1列に並べて、今どこにいるかを見せる。押すとその工程がある画面に移る。
- 状態: 工程ごとに 未実行 / 実行できる / 処理中 / 完了 / エラー / 古い
- 機能: 工程の進み具合の表示

#### 4. 工程実行ボタン
- 役割: 工程を1つ実行する。どの画面でも同じ部品を使う。
- 状態:
  - 未実行: 押せない。理由を出す（例:「先に音源を追加してください」）
  - 実行できる: 押せる
  - 処理中: 経過時間を出す。「中止」に変わる
  - 完了: 「やり直す」に変わる
  - エラー / 中止: 「もう一度実行」に変わる
- 機能: 処理中・失敗の表示とログ

#### 5. 処理状況バーとログ
- 役割: 画面の下に、実行中の工程と経過時間を出す。「中止」ボタンを持つ。開くと出力を見られる。
- **ログは2種類。**「かんたん」は工程が出したことだけ（SSE で流れる）。「くわしい」は ffmpeg などの出力もぜんぶで、`ep*/00_logs/<工程>.log` に残る。コマンドで動かしたときも同じように残る
- **くわしいログは、その工程を動かすたびに上書きされる**（`build.py` の `open_detail_log` が `"w"` で開く）。前回の失敗の様子を残したいときは、動かし直す前にファイルを別名で控える
- **`00_logs/` には相談チャットの記録（`chat.json`）も入っている。** ログの掃除のつもりでフォルダごと消すと、会話が消える。消すなら `<工程>.log` だけにする
- 状態: 何もしていない / 処理中 / 完了（数秒で消える） / エラー（エラー文を出したまま、ログを開ける） / 中止
- 機能: 処理中・失敗の表示とログ

#### 6. 相談チャット
- 役割: この回の文字起こしを読んだ Claude に相談する。右側で開閉し、どの画面からでも使える。
- 表示: 会話、入力欄、何を読んでいるか（確定版 / 下見 / 文字起こしなし）、「会話をリセット」「改善メモに残す」ボタン
- **「読んでいるもの」は、会話を始めたときに渡した版を出す。** 材料は1回目にしか渡していないので、あとで確定版ができても Claude が覚えているのは渡した版のまま。ずれたら「会話をリセットしてください」と出す（#8）
- 状態: 会話なし / 返事待ち / エラー
  - エラーはチャットの中に出し、**送った質問は消さない**。「もう一度送る」を置く
- 機能: Claude に相談するチャット

#### 7. 改善メモの下書きダイアログ
- 役割: Claude が会話を要約した下書きを確認・編集し、Issue に登録する。
- 入力: タイトル、本文（ラベル `改善メモ` は自動で付ける）
- 状態: 下書きを作成中 / 編集中 / 登録中 / 登録済み（Issue へのリンクを出す） / エラー
  - **登録中は閉じられない**（閉じると結果が伝わらず、二重に登録しかねない）
  - **公開リポジトリの Issue に出ることを、ダイアログに書く。** 保存先を決めたのは 2026-09-14、リポジトリが公開になったのは 2026-09-17 で、前提がずれていたため（#8 のレビュー）
- 機能: 会話から改善メモに残す

### 1. 回の設定

#### 8. コーナー・テーマ編集
- 役割: `config.yml` の `segments` を編集する。
- 表示: コーナーごとに1行（コーナーの種類を選ぶ + テーマを入力）。行の追加・削除。
- 状態: 保存済み / 未保存の変更あり / 保存中 / エラー
- 機能: テーマ・コーナーの設定

### 2. 収録〜整音

#### 9. 音源の追加
- 役割: 収録ファイルを取り込む入口。NotebookLM の「ソースを追加」のように、1つのパネルから方法を選ぶ。
  - ファイルをドロップ / ファイルを選ぶ
  - OBS のフォルダから選ぶ: 見張っているフォルダの録画を新しい順に並べ、選んで取り込む
- 状態:
  - 空（まだ音源がない）
  - ドラッグ中（落とせる場所を強調）
  - 取り込み中（録画から音声を取り出している）
  - エラー（対応していない形式 など）
  - OBS のフォルダが未設定 / 見つからない
- 機能: 音源を追加

#### 10. 収録ファイルカード
- 役割: 取り込んだ収録ファイルを1枚のカードで見せる。
- 表示: ファイル名、長さ、形式（wav / m4a / OBS の録画）、録った日時、「差し替える」ボタン
- 状態: 音声を取り出し中 / 使える / エラー
- 機能: 音源を追加

#### 11. 音声プレーヤー
- 役割: 音声を再生する。見た目と操作は `playerRow()` で共通にする。
- 表示: 再生・停止、シークバー、現在の位置 / 長さ
- 状態: 音声なし / 停止中 / 再生中
- **プレーヤーは音ごとに分かれている。再生位置は共有しない**（#36）。
  時間の基準が違う音を1つのプレーヤーで鳴らすと、トリムで削った秒数のぶんだけ
  再生位置がずれるため（ep01 では 2.5秒ずれていた）

  | どこ | 鳴らす音 | 時刻の基準 |
  |---|---|---|
  | 画面2 部品12（下見の文字起こし） | `00_raw` の録音 | 下見の行の時刻 |
  | 画面2 部品13（波形とエコー区間） | `01_clean/trimmed.wav` | エコー区間の時刻 |
  | 画面2 部品15（整音結果） | `01_clean/clean.wav` | 整音後 |
  | 画面3 部品12（確定版の文字起こし） | `01_clean/clean.wav` | 確定版の行の時刻 |

- **鳴るのは常に1つだけ。** どれかを再生したら、ほかの音と動画は止める
- **読み上げには、どの音かを言う**（#59）。「下見を再生」「波形を再生」「整音結果を再生」「動画を再生」。画面では見出しで分かるが、キーボードや読み上げで辿ると分からないため
- 機能: 下見の文字起こし、確定版の文字起こしの確認と修正

#### 12. 文字起こしリスト
- 役割: 文字起こしを時刻つきで並べる。行を押すと、その位置から再生する。再生中の行を強調する。
- 下見（`scan.json`）と確定版（`transcript.json`）の両方で使う。
- 確定版では、聞き間違いを直せる。
  - 行の文字を押すと、その場で書き換えられる。書き換える間も、その行を聴き直せる。
  - 直した行には印を付け、元の文字起こしも見られるようにする。
  - 下見は読むだけで、直せない（カット点を探すためのものなので）。
- 状態: 未実行 / 処理中 / 表示 / 編集中 / 未保存の変更あり / 保存済み / エラー
- 機能: 下見の文字起こし、確定版の文字起こし、確定版の文字起こしの確認と修正

#### 13. 波形ビュー
- 役割: 波形を出し、ドラッグで区間を選ぶ。選んだ区間を帯で見せる。
- 主な使い道は、エコーをかける区間の指定と、整音後の確認。
- 状態: 読み込み中 / 表示 / 失敗 / 区間を選択中
- **wavesurfer.js で描く（#36）。** ファイルは `web/static/vendor/` に置いてあり、CDN からは読まない（ネットが切れても波形が出るように）。詳しくは `web/static/vendor/README.md`
- **形（peaks）はブラウザが wav を読んで作る。** サーバーが返すのは音の在りかと長さだけ。区間を伸び縮みさせても形が崩れない代わり、音を丸ごと読み込む。**その間は「音を読み込んでいます… N%」を出す**
  - 待ち時間: 10分の回（57.6MB）を、画面2 と同じく波形2枚ぶん同時に読ませて **1.7秒**（WSL のブラウザで実測）。JS のメモリは約100MB
  - **読み込み中は、箱の中に重ねて出す**（#59）。箱の外に小さい文字だけだと、真っ黒な箱が「壊れている」ように見えるため
  - 動いていることは、**処理状況バーと同じ「流れる帯」で見せる**（部品5 と見せ方をそろえる）。見本も直した（Claude Design の「部品13の読み込み中.dc.html」が正。screen2 の「中央にくるくる」は採用しない。#70 で決めた）
  - くるくる（`spin`）は #69 で回るようになったが、**ここは帯のまま**。「待っている」の見せ方を画面の中で2種類に分けないため
- **区間はドラッグで選び、端を掴んで伸び縮みさせられる**（wavesurfer の Regions プラグイン）。0.3秒より短い選択は区間にせず、その位置へ飛ぶだけにする（`build.py` の `ECHO_MIN` と同じ）
- **波形は自分の音を持つ（`01_clean/trimmed.wav`）。** 部品11 の下見のプレーヤーとは別物で、再生ボタンも別にある
  - 分けた理由: 下見の文字起こしの時刻は `00_raw` の録音が基準、エコー区間の時刻は前後をトリムした `trimmed.wav` が基準。**1つのプレーヤーを共有すると、トリムで削った秒数のぶんだけ再生位置の線がずれる**（#36 で見つけた。ep01 では 2.5秒ずれていた）
- **帯の見た目は `style.css` では決められない。** wavesurfer は波形を shadow DOM の中に描くので、CSS が届かない。`app.js` の `WAVE_CSS` を器ごとに差し込んでいる
- 部品が読めなかったときは、波形の代わりに理由を出す（黙って空にしない）。**失敗の色は、ほかの画面（`.save-error` など）と同じ赤にそろえる**（#59。アクセント色だと「エラーではないお知らせ」に見える）
- 機能: エコーなどのエフェクト（整音後の試聴は部品15。ここで鳴るのはエコーをかける前の音）

#### 14. エコー区間リスト
- 役割: エコーをかける区間を並べる。
- 表示: 区間ごとに1行（開始・終了の時刻、プリセット「なし / 軽め / 響く」、「この区間を試聴」、削除）
- 状態: 区間なし / 未保存の変更あり / 保存済み / 試聴用の音を作成中
- 機能: エコーなどのエフェクト（区間指定）

#### 15. 整音結果パネル
- 役割: 整音後の音声を聴いて確かめる（1つ目の確認ポイント）。
- 表示: 音声プレーヤーと波形、長さ、前後で削られた秒数、「確認した」ボタン
- **波形は `01_clean/clean.wav` から出す**（#36）。聴いている音そのものなので、長さも形も一致する。再生済みのところは色が変わる。ここも部品13 と同じ wavesurfer で、自分の再生ボタンを持つ
- **エコーをかけた所は帯で見せる**（#42）。部品13 と違って、**掴んで動かせない**（できあがった音なので直せない。直すなら部品14 で区間を変えて整音をやり直す）
  - **掴めない帯には斜線を重ねる**（#65。Claude Design で3案を出し、ユーザーが案Aを選んだ）。掴み手の有無だけでは、離れて見たときに気づけなかったため
  - **斜線だけに頼らず、言葉でも言う**: 「斜線の所にエコーがかかっています（ここでは動かせません。…）」
  - **エコーをかけたのに帯が出せないときは、そう言う**（#61）。黙って帯を出さないと「エコー無し」と見分けが付かない。起きるのは `trimmed_duration` を持たない古い `clean.json` が残っている回だけ
  - **帯の時刻は、置き直してから出す。** `clean.json` に残っているのは `trimmed.wav` の時刻で、`clean.wav` はそのままの位置ではない
    - `aecho` は、いちばん遅いエコーの遅れぶん（軽め 0.07秒 / 響く 0.21秒）その部分を**伸ばす**
    - `acrossfade` は、継ぎ目ごとに 0.02秒 重ねて**縮める**
    - 後ろの区間ほど、前の区間のぶんが積み上がってずれる。計算は `build.py` の `echo_positions`（`echo_graph` と同じ分け方をたどるので、片方だけ直してずれることがない）
- 「確認した」は押さなくても次の工程に進める。押したら工程ステッパーに印を付ける。
- 状態: 未実行 / 処理中 / 完了（未確認） / 完了（確認済み） / 古い（音源やエコーを変えた） / エラー
  - 「確認した」の印は `01_clean/confirmed`。`clean.wav` より古ければ「未確認」に戻る（やり直したら外れる）
  - **「古い」の判定**: 音源（`00_raw`）が `clean.wav` より新しいか、`config.yml` の `echoes` が `clean.json` に記録した「実際にかけた区間」と違うとき。`config.yml` には飛ばされた区間も残るので、比べる前に `normalize_echoes` を通す
  - 「古い」の間は「確認した」を押せない（作り直してから確認する）
  - ~~処理中・エラーの見せ方は、いまは下の処理状況バーだけ。~~ #42 でパネルの中にも出した。処理中は「処理中 00:42」＋動く帯＋中止、エラー・中止は理由＋「もう一度実行」
  - **確認済みになるとバッジが塗りつぶし＋チェックの「確認した」に変わり、ボタンは消える**（もう押す必要がない）
  - 表示は `01_clean/clean.json`（整音のときに残す）から読む。**削られた秒数は「前後で N秒」までで、先頭と末尾の内訳は出さない。** 内訳を出すには、先頭だけのトリムをもう一度かけて測る必要があるため
- 機能: 前後のトリム、整音後の試聴

### 3. 仕上げ

#### 16. メタデータエディタ
- 役割: Claude が作ったタイトル・概要欄・章・タグを直す。
- 表示:
  - タイトル（文字数。60文字を超えたら警告）
  - 概要欄
  - 章（時刻 + 見出しの行。追加・削除。時刻を押すとその位置から再生）
  - タグ（チップ。追加・削除）
- 状態: 未生成 / 生成中 / 保存済み / 未保存の変更あり / エラー
- 機能: タイトル・概要欄・章の生成と編集

#### 17. 保留チェック
- 役割: メタデータに「（保留中）」が残っている、章がない、などを見つけて警告する。
- **問題がある間は「コピー」を押せない。** 動画化は止めない（#7 で決め直した）。`step_video` は `clean.wav` と `config.yml` の `images` しか読まず、メタデータは動画に入らないため。止める実益が薄く、章が無いだけで動画を試せなくなるほうが手戻りが増える
- 表示: 問題の一覧（例:「タイトルが（保留中）のままです」）。問題がなければ何も出さない。
- 状態: 問題なし / 問題あり
- 機能: タイトル・概要欄・章の生成と編集（保留チェック）

#### 18. コピーボタン
- 役割: YouTube に貼るために、タイトル / 概要欄（章・クレジットつき） / タグをクリップボードにコピーする。
  - **クレジット（`VOICEVOX:ずんだもん`）は規約で要る**（#137）。`build.youtube_description` が毎回足す。
    **入っていないときは、コピー欄に「（クレジットなし）」と出す。** 落ちても気づけない形にしない
- 状態: 通常 / コピーした（数秒だけ表示） / 押せない（保留チェックで問題あり）
- 機能: YouTube に貼るためのコピー

#### 19. 動画プレビュー
- 役割: 完成した動画を再生する。
- 表示: 動画、長さ、ファイルの場所、大きさ（1920x1080）、容量、「フォルダを開く」
- **再生ボタンとシークバーは自前**（#42）。ほかの部品（11・13・15）と同じ `playerRow()` を使う。ブラウザ標準のコントロールはほかの画面から浮くため
- **絵の中央にも大きな再生ボタンを重ねる**（#64）。動画だけは「サムネイルを押す＝再生」の慣習が強いので、下のボタンと両方置く。**止めている間だけ出し、再生中は絵を隠さないよう消す**
- **再生前は、動画の1コマ目を出す**（#42）。`04_video/poster.jpg` に切り出して置く。**実際に再生したときに出る絵と同じ**になる（1920×1080 に余白を入れた形）
  - 動画より新しいポスターがあれば作り直さない。動画を作り直したら作り直す
  - 作れなかったときは、理由をパネルに出す（`ffmpeg` が無い、など）。**絵が無いだけで動画パネルを消さない**
- **動画の器は描き直しで作り直さない。** 作り直すと再生が止まる（`videoView`）。回とタブを切り替えたときは、見えない場所で鳴らないよう明示的に止める
- **章マーカーは動画に焼き込まない。** `meta.json` の章をプレビューの横に並べ、押すとその位置から見られる形にした（#7）。見本にある「動画の章マーカーが前のまま」という注意書きは、焼き込んでいないので出さない
- 状態: 未実行 / エンコード中 / 完了 / 古い（整音をやり直した） / エラー
  - ~~「古い」はいま工程実行ボタンの脇にしか出ない。~~ #42 でパネル本体にも出した。黄色い枠＋「古い」バッジ＋理由＋「動画をやり直す」
  - 動画の URL に更新日時を付ける。作り直したときに、古い動画が出ないように
  - メタデータを直しても「古い」にはしない。`build.py` の `step_video` は `clean.wav` と `config.yml` の `images` しか読まず、`meta.json` を使わないため（2026-09-19、#21 のレビューで判明）
- 機能: 動画化とプレビュー

## 未保存のまま閉じない

保存していない変更があるときは、**回を移るときと、画面を閉じる／読み込み直すときの両方**で知らせる（#60）。
数えているものは1か所（`app.js` の `unsavedThings()`）にまとめてある。

| 何が未保存か | どこで直すか |
|---|---|
| コーナー・テーマ | 画面1 部品8 |
| エコー区間 | 画面2 部品14 |
| 文字起こしの直し | 画面3 部品12 |
| 書きかけの行（まだ確定していない） | 画面3 部品12 |
| タイトル・概要欄 | 画面3 部品16 |

閉じるときの文言はブラウザが決めるので、こちらでは選べない。

- **まだ確定していない行も数える。** 確定（Enter /「この行を確定」）を通るまで `state.texts` は変わらないので、
  数えないと打ちかけが黙って消える（#70 のレビューで見つかった）
- **数えられなかったときは「無い」ことにしない。** 途中で失敗したら「保存していないもの」として確認を出す。
  黙って閉じさせると、この仕組みで防ごうとしたことがそのまま起きる

## 見分け方のルール

同じ形のものが「触れる／触れない」で並ぶときは、**見た目と言葉の両方**で見分けられるようにする。
片方だけだと、離れて見たときか、読まなかったときに気づけない。

| 場面 | 見た目 | 言葉 |
|---|---|---|
| 部品13 の帯（掴める） | 両端にクリーム色の掴み手 | 「波形をドラッグして区間を選び…」 |
| 部品15 の帯（掴めない） | **斜線を重ねる**。掴み手を出さない | 「斜線の所にエコーがかかっています（ここでは動かせません…）」 |

これは #65 で決めた（掴み手の有無だけでは足りないとデザイン担当が指摘し、利用者担当と意見が割れた）。
次に似た部品を作るときも、この形にそろえる。
